# 改修詳細設計・検証記録

作成：2026-10-22。対象方針：[REFACTOR_PLAN.md](REFACTOR_PLAN.md)。以下に段階A〜Dで実装したAPI・状態遷移と検証結果を記載する。過去の場面設計資料の計測値は履歴として保持し、本書に今回の結果を記録する。

## 段階A：保存ブリッジ

### 責務

- `tools/export_server.js`：旧描画関数の公開、CLI起動。通常は生成せず待機。
- `tools/export-bridge.cjs`：HTTP・認証・入力検証・容量制限・ジョブ管理・排他的保存。
- `tools/export-job.cjs`：独立プロセスで旧描画とffmpegを実行。フレームごとにstdinのbackpressureを待つ。
- `engine/bridge-client.js`：現行・旧版共通のセッション取得とPOST。トークンはメモリ内のみ。

### API（protocol 2）

全ルートでHostとOriginを照合する。許可Originの初期値はlocalhost:8790と127.0.0.1:8790。追加Originは環境変数`EXPORT_ALLOWED_ORIGINS`のカンマ区切り完全一致。Originなし・nullを拒否する。`GET /health`は`{ok,protocol}`、`GET /session`は`{ok,protocol,token}`。レスポンスはno-store。保存はPOSTのみ、`X-Picnic-Token`必須。

| パス | 入力 | 成功 |
|---|---|---|
| `/save-blob?filename=...&convert=mp4` | 元形式のPNG/WebM/MP4のbodyとContent-Type。convertは動画のみ任意 | `{ok,filename,mime}` |
| `/save-png` | JSONのmode/t/light/wave/caustics | 同上 |
| `/save-video` | JSONのmode/duration/light/wave/caustics | 同上 |

不許可403、未知404、メソッド違反405、入力不正400、容量超過413、処理中429、変換失敗422、期限超過504。保存先絶対パスや内部例外を返さない。受信と生成を含め同時1件、受信64MiB、JSON 4KiB、出力128MiB、受信から公開まで120秒、受信30秒。設定はサーバー生成時に注入可能とし、テストでは小さくする。型とシグネチャを照合するが、完全なメディア検証とは扱わない。動画はffmpegの終了コードと出力を検証する。

保存先直下に専用一時ディレクトリを作る。変換後にランダム接尾辞を付けたファイル名へ、同一ファイルシステム内のハードリンクで排他的・原子的に公開する。公開処理の前後に中断を検査し、期限切れ・切断なら公開したファイルも削除する。作業領域の削除中に切断された場合も、応答確定前に最終ファイルを取り消す。既存ファイル・リンクは上書きしない。失敗・切断・期限切れでプロセス群と作業領域を片付ける。POSIXでは独立プロセスグループを終了し、Windowsではtaskkillのプロセスツリー終了を使う。

接続表示はトークンキャッシュを使わず毎回 `/health` をno-storeで照会する。失敗時はキャッシュしたセッションも破棄する。セッション確立失敗時はブラウザ保存。403は新しいセッションを一度取得して再送できる（認証で拒否され副作用がないため）。送信後の通信断は保存結果不明として区別し、同じPOSTを自動再送しない。録画Blobは元MIMEのまま送り、成功時だけサーバーの確定名を表示する。

旧2D版はGET・iframe・no-cors要求をやめ、既存のブラウザ保存を維持して認証POSTで旧生成を要求する。旧3D版は同じ共通クライアントでBlobを送る。公開サイトでは許可Originに入らない限りブラウザ保存を使う。

## 段階B：回復・入力・メモリ管理

`capture`はidle/preparing/recording/savingを保持し、busyとrecordingを区別する。録画の成功・例外・errorイベント・手動停止を一度だけ確定する。全経路でトラック停止・固定解像度解除を行う。PNGのnull、未対応API、開始例外を明示的にrejectする。ページ側のfinallyでUIと開始前の交通/散策を戻す。結果URLはdisposeを備え、次の結果表示時に旧結果を解放する。

Workerの各範囲は生成・送信・実行・取り込みの失敗をPromise.catchで捕捉し、その範囲だけ同じ関数で代替計算する。タイムアウトは30秒を初期値とする。Workerはfinallyで終了し、代替計算の例外は呼び出し元へ伝える。読み込み画面はエラー表示に更新する。失敗時は開始画面を隠し、エラー画面を最前面に表示して再読み込みボタンを操作可能にする。

playerは`walking`の意味を維持して`movedDistance`を追加。updateごとに0へ戻し、実際に進んだ距離を設定する。姿勢解除は移動距離を累積し、0.15mを超えたら立つ。カメラの上向きpitchとボタンも解除する。URL設定はhasOwnで検証し、URL→保存値→既定値の順に有効値を選ぶ。

## 段階C：草

uTimeは毎フレーム更新。カメラのworld/projection行列が一致する間は配置計算しない。タイル高さをキャッシュし、選択タイル列が同じなら行列転送を省く。invalidateで明示的な再計算を可能にする。測定用に配置更新数と転送数を提供する。

## 段階D：書き出しUI

`engine/export-ui.js`がbusyガード、結果の所有・解放、エラー表示、録画UIのfinallyを担当。ページは開始準備（波紋・散策・交通）とその復元関数を渡す。各ページの地形・施設・視点の組み立ては共通化しない。

### 実装時に確定した補足

- 最終ファイルにはUUID接尾辞を付ける。元ファイル名はUTF-8で160 bytes以内とし、Windowsの代替データストリーム等を避けるためコロンや予約記号も拒否する。
- 出力容量は100msごとのサイズ監視と公開前の検証で制限する。ffmpegのファイルサイズ停止オプションは途中までの動画を正常終了扱いにする可能性があるため使わない。この監視はOSのディスククォータではなく、一時ファイルは監視間隔内に一時的に上限を超え得る。超過時はジョブを終了し出力を公開しない。
- POSIXでは描画ジョブとffmpegのプロセスグループ全体を終了する。Windowsは `taskkill /t /f` で子孫も終了する分岐を用意したが、Windows実機は未検証。
- ブリッジ変換後の「もう一度保存」は、ブラウザに保持している元Blobを保存する。元データがWebMで保存先が変換済みMP4の場合は「元のWebMをもう一度保存」と明示し、リンクのdownload名にも `.webm` を使う。変換後のMP4名を元WebMへ付けない。
- 確認応答が届かない送信は再送しない。ブラウザ保存へ移り、保存結果不明の注意を表示する。保存先に既に作成されている可能性があるため、利用者が保存先を確認できる表現にした。
- 手動移動では実移動累計0.15mで姿勢を解除する。単なるキー入力で解除する処理は除き、壁に向かって入力するだけの場合を区別した。タップ自動歩行は開始時に立つ。
