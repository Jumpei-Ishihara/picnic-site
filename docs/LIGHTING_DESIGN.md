# ピクセルアートの光表現 詳細設計・検証記録

**現在の適用状況：なぎさ・picnicとも、木漏れ日の改善を保持し、ブルーム・明部圧縮・光線設定は旧方式へ切戻し。picnicのカメラ／影更新順・6秒周期の修正も保持。** 詳細は[夕景の劣化分析・切戻し](SUNSET_REVIEW.md)。以下の初回試作結果は履歴として残す。

作成：2026-10-24。対象方針：[LIGHTING_PLAN.md](LIGHTING_PLAN.md)。対象：なぎさ・picnic。実装と検証をこの資料に追記する。

## A：木漏れ日

`createLeafKit({ loop, softDapple = false })` により、影の穴だけを改善する。既定falseは従来の格子ハッシュ判定。trueでは光に垂直な平面上の32×32・1KBの繰り返しノイズテクスチャを線形補間して大小2スケールで混ぜ、まとまりのある穴を作る。フラグメントごとの多数のsinハッシュを2回のテクスチャ参照へ置き換えた。正弦・余弦の風はloop秒周期。光方向に平行な同じ線上では同じ穴を使用し、葉の表裏で穴が塞がらないようにする。光が基底軸と平行な場合は別軸を選び、ゼロ長ベクトルを避ける。

なぎさでのみsoftDappleを有効化。picnicの重複した深度材質・leafifyを共通キットへ置換し、既存の色斑・3色塗り・季節の材質を維持する。光方向は光の位置からtargetを引いた方向。時刻はloop周期で折り返す。

## B：ブルーム・明部

`createPixelRenderer`の`softLighting`は既定falseとし、対象2ページだけtrue。HDRの色・深度・法線の既存バッファを使用し、追加のシーン描画やレンダーターゲットを作らない。

新プロファイルは線形色の輝度で滑らかに明部を抽出し、RGBの比率を保つ。近傍1〜2ドットの既存12参照に、弱い広域の4参照を追加する。広い光は低強度に留め、すべて低解像度で合成する。明部の最大成分が0.8を超えた部分だけ連続した肩カーブで圧縮し、色比率を保つ。sRGB変換を一度行い、既存の色調整・ディザ・減色を通す。輪郭の通常描画やCSS拡大に平滑化を追加しない。

輝度抽出は0.95〜1.45のsmoothstep。広域は4ドット離れた上下左右を各0.16の重みで追加。色の圧縮は `mappedPeak = 0.8 + 0.2 * (1 - exp(-(peak - 0.8) / 0.2))` とし、RGB全体に `mappedPeak / peak` を掛ける。暗部と中間調はこの圧縮で変更しない。

キットのノイズと深度材質はページ寿命中に共用し、`dispose()`を提供する。ループ長0・負・非有限を拒否し、光の位置とtargetが一致した場合は上方向を代替にする。従来プロファイルにもこの異常方向の保護を適用する。

## C：空中の光・太陽の光芒

24サンプルの影マップ・レイマーチと20サンプルの画面上の光芒を維持。新プロファイルでは光の影範囲外を発光の根拠にしない。深度の手前までに制限した短距離を積分し、カメラからの距離で減衰。既存の地面付近に濃い密度と前方散乱を調整する。新しい`baseHeight`引数で足元の地形高を渡し、なぎさの丘（約10m）でも海抜0m基準で光が消えないようにする。完全な多重散乱・物理的な透過積分は今回の対象外。

積分位置は `len * (0.45*t + 0.55*t*t)`、重みはその微分 `0.45 + 1.1*t`。距離減衰は `exp(-distance*0.035)`。影座標のxy/zが0〜1の内側でのみ光を加える。前方散乱は `0.12 + 1.2 * max(dot(view,light),0)^6`。なぎさは28m、picnicは24mの範囲を対象にする。

画面上の光芒は従来合成の0.35倍を上限とし、太陽近傍の補助として弱め、太陽高度と日中の重みで制御する。なぎさは共通`createLook`にオプションを追加して既存の他ページから分離。picnicも太陽方向の高さで日中の光を制限する。夜の灯りのブルームは維持し、月光の空中光線は強めない。

picnicでは現在フレームのカメラ行列を光芒計算前に更新し、反射前に`prepareShadows()`を呼ぶ。水面にも現在の木漏れ日の影を反映し、1フレーム前の影との不一致を避ける。PNG用の再描画にも同じ順序を使う。picnicの草・水・樹木・アヒル等の時刻は6秒で折り返し、花びらの横揺れの12秒周期を6秒へ揃えた。これは周期境界の実画像比較で検出した既存の不一致への修正。

## 検証方法

`tools/validate-lighting.cjs before|after`。ローカル静的HTTPサーバーとPuppeteer/Chromeを使用。1280×720、DPR1、夏、描画320×180固定、rAFを止めて`step(0)`で同じ構図を比較する。12フレーム×8バッチのGPUクエリと同期待ち込みのCPU時間を記録。ウォームアップ10フレーム後に測定する。検証用の`THREE_LOCAL`指定では、同じCDNのr160を取得したローカルコピーでそのURLだけを応答し、CDNの待ち時間を切り離す。アプリのimportmapは変更しない。GPU非対応ならnullとし、CPU時間をGPU値と呼ばない。通常の60fps動作やモバイル実機の性能保証とは区別する。

画像は昼・見上げ・夕日・夜を保存し、視覚確認する。動き、PNG/動画、他場面の起動・旧プロファイルは追加で検証する。自動回帰テストはループ・方向・明部抽出・範囲外などの境界条件を中心とし、実GLSLはブラウザでコンパイル確認する。

## picnic夕景の確認・切戻し（2026-10-24）

### 結論・変更範囲

picnicでも初回試作により、樹木の縁と水面を包む暖かい光が弱まり、夕景が暗く平坦に見える劣化を確認した。`picnic.html` の `createPixelRenderer` から `softLighting: true` を外し、`updateLook()` の光線・空中光設定を旧方式へ戻した。昼・夕景・夜に同じ旧プロファイルを使う。

- 復元：旧ブルーム、チャンネルごとの明部クリップ、20サンプル光芒の従来強度、24サンプル空中光の従来積分。空中光の距離28m、強度は昼0.3・朝夕1.1・夜0.35の重み付け。
- 光芒は元の `sd.y > 0.02 ? warm * 0.9 : 0`。追加した`daylight`と描画側0.35倍はpicnicで無効化。
- 保持：共通leafKitの木漏れ日、target相対の光方向、現在フレームのカメラ行列・反射前の影更新、草・水・花びら等の6秒周期の修正、既存の保存処理。
- なぎさ・他3ページの光表現は今回変更していない。試作用の新しい描画プロファイルは共通モジュールに残るが、現行5ページでは全て無効。

### 切り分けと原因

夏・18.35時・カメラ`[1.3,1.1302342,-1.75]`、太陽高度7.898度、表示1280×720／描画320×180。時刻とアニメーションを止め、24フレーム描画後に比較。改修前はコミット0394ced9のpicnic・描画・樹木等を使用し、試作と各単独復元をブラウザのリクエスト差替えで再現した。HUDは全条件で非表示。`SUNSET_SCENE=picnic THREE_LOCAL=… node tools/review-sunset.cjs` で再現できる。

1. 光芒のuniformは0.649038→0.210337。さらに新プロファイルの描画側0.35倍が掛かり、実効強度は元の**約11.34%**になっていた。係数0.9→0.5と`1-night`による減衰が重なった。この時刻では太陽高度のsmoothstep部分は既に1で、なぎさの低高度の例とは異なる。
2. 空中光のuniformも0.939103→0.294471、積分距離28→24mへ縮小し、距離減衰・散乱方向等も変更。picnicでは、空中光単独の復元も広い暖色の光の回復へ大きく寄与した。
3. 明部圧縮は強い逆光を戻した際にも輝きの芯を抑える。ブルーム単独の復元は、この構図の広い環帯の指標にはほとんど影響しなかった。ブルームの近傍効果や他場面での影響がないという意味ではない。

太陽中心から12〜48描画ドットの環帯6784画素を測定。表示RGBに0.2126/0.7152/0.0722を掛けた平均と、0.7を超える画素の割合を記録した。物理的な輝度や美しさの点数ではなく、目視比較の補助指標。

|---|---:|---:|
| 改修前 | 0.381078 | 19.47% |
| 劣化した試作 | 0.303194 | 0.10% |
| 光芒だけ戻す | 0.340522 | 0.10% |
