# なぎさポニーランド 詳細設計・検証（2026-10-27）

[改修方針](PONY_PLAN.md) の段階A〜Eに対応する。実装と検証の最新仕様は本資料を優先し、`NAGISA_DESIGN.md` の初期版の位置・頭数・歩行説明を現行仕様として扱わない。

最新の結果は本書「再レビューと追加修正（2026-10-27）」と[再検証の証跡](pony-validation/review/index.html)を参照。初回検証で使った地形高さとの一致だけでは、描画した走路への接地を保証できなかったため、今回検証方法も修正した。

## 設計

### A 施設配置

円形囲い（中心x=-165.6,z=-46、白い柵、周回個体0）と東の乗馬スペース（中心x=-148.5,z=-48.5、走路平均半径4.3m、周回3頭）を分離。北の馬場、厩舎、放牧場、乗り台の座標は推定値を維持。`style:none`では内柵と中央小屋を作らない。コースの半径は実測値ではない。

ポニー用の接地基準は`createGridGround`で近景地形の実際のインデックス三角形を補間し、さらに`createTrackGround`でその上の走路を補間して求める。走路は地面の約0.04m上に描くため、元の地形高さを直接蹄へ使わない。待機・放牧も円形囲い・乗馬走路・近景地形の最も高い支持面を共用する。走路の三角形は2mセルに登録して局所検索し、実行時の各脚にレイキャストは使わない。

乗り台は公式写真に合わせて緑色の3段に変更し、静的部品を1メッシュに結合。`PL.yard`の同じ矩形をプレイヤーの立入制限にも追加し、茶色の柵を通り抜けて乗馬コースへ歩ける不整合を解消した。入口の門は外観として残し、場内の乗降体験は実装しない。

### B〜D ポニーと動き

ポニーをヤギのモデルから分離。共通形状と材質を再利用し、胸・腰・頭・耳・口吻・蹄・鞍をピクセル画面で読める大きさにする。首の階層に頭・たてがみを配置する。脚は股/肩、関節、蹄の2節構成。

円の接線方向に体を向け、6秒で1頭分進む（3頭で1周18秒、約1.50m/s）。歩行は6秒に8ストライド。支持期は蹄の世界座標を固定し、遊脚期は次の接地点へ滑らかに移す。接地点ごとに上記の描画支持面の高さを取得し、2節の解析的IKで脚を曲げる。過大な傾斜は関節長で制限し、実地の測量や物理シミュレーションの代替にはしない。

乗り手は鞍基準、引き手は進行方向の前寄り内側。手綱は頭絡の接続点と手の位置から3頂点の折れ線として更新する。採食は首の回転と根元の高さを連動、待機は小さい首・尾の動きとする。耳は輪郭の追加のみで独立した耳の動きは今回は実装しない。

手は引き手のポニー側の腕の先端に付けた可視メッシュとし、その世界位置へ手綱を接続する。斑模様は胴体に沿う曲面とし、白い毛色だけを条件に模様を付けず、現在の待機個体の毛色とたてがみの組合せを区別する。

`realsite/pony.js`が形状・歩行・IKを担当し、`nagisa-facilities.js`は施設配置・人・手綱を担当する。ヤギは従来の`makeQuadruped`を維持。共通の材質を持つ体・頭などは形状を結合し、同じ毛色の個体間でも共有する。脚12部品は個体ごとに1つの`InstancedMesh`で描画。可動範囲を覆う固定の境界球を与え、視錐台判定を維持する。

静止時は脚の解が変わらないため、首・尾のみを更新する。脚は初回、ルート/親の変換変更、接地関数変更、歩行後、`invalidateFeet()`時に再計算する。地形は静的であることを前提とする。インスタンスの更新フラグは1姿勢につき1回だけ設定する。

### E ループと負荷

6秒後に周回個体が次の位置へ入れ替わる。周回個体の材質・歩行位相は同一、尾の位相は円周位置に依存させ、空間ごとの姿が連続するようにする。静止個体には固定の毛色・斑模様と6秒周期の動きを与える。更新は時刻から算出し、フレーム数に依存しない。

歩行は支持期64%、遊脚期36%。四肢の着地位相はLF=.75、RF=.25、LH=.5、RH=0。支持期の中央時刻における接地点を固定し、遊脚はsmoothstepで次の接地点へ移動する。持ち上げ量の最大は0.105m。地形の途中の盛上がりも参照する。脚長は上0.34m、下0.33m。蹄上端に0.07mの厚さ分を加えてIKを解き、蹄下面を目標位置に合わせる。現地の脚長や歩幅を実測した値ではなく、ピクセル表示のためのモデル値である。

録画の初期化で見つかった既存の問題にも対応した。`captureStream()`が直前のPNG保存で使ったキャンバスを先頭フレームとして拾う可能性があったため、`createCapture`に任意の`prepareVideo`を追加。固定解像度へ変更→初期姿勢準備→描画→コピー→ストリーム作成の順とした。なぎさでは準備時に`elapsed=0; step(0)`で全体を0秒へそろえる。初期化が失敗した場合も解像度とbusy状態を解除する。共有APIの従来の呼出し方も維持する。

### 検証方法の補強

初回の4,320点の目標値誤差は、目標にした高さ自体が描画面と異なるため、接地の十分な証拠ではなかった。今回の判定はソルバーと別の`THREE.Raycaster`で、実際の走路・近景地形の三角形と蹄下面を比較する。非平面の格子で、双一次補間が0.25m、描画三角形が0.5mとなる条件も回帰テストへ追加した。

ページが時刻を6秒で折り返す比較だけではなく、ポニーを直接0/6/12秒へ更新し、影・反射も更新してから画像を比較する。シェーダーのconsoleエラーも収集し、GLエラーと別に失敗判定する。

### セキュリティと残る制約

今回の変更範囲では、新たなセキュリティ上の修正必須事項は検出しなかった。追加処理は固定の場面データと既存のThree.js上の計算であり、外部依存・通信先・ユーザー入力からのコード実行・HTML挿入・ファイル保存経路は追加していない。共有の保存処理は、初回に追加した初期姿勢準備を含めて再確認し、既存のOrigin/Host・認証・容量制限・失敗後の解放・再試行の回帰テストが成功している。これは今回の差分レビューとローカル検証の結果であり、全環境での安全性の保証ではない。

実在施設の最新寸法・個体、実機スマートフォン/iOS Safariでの性能と保存、引き手自身の足接地や独立した耳の動きは引き続き未検証/対象外。走路の位置・形状や地形を再生成する実装を将来追加する場合は、接地サンプラーの再作成と静止脚キャッシュの無効化が必要。`createGridGround`は近景地形と同じ座標系・2三角形/セルの格子を前提とする。

## 再実行手順

静的サーバーを127.0.0.1:8790で起動し、Three.js r160のコピーを`/private/tmp/picnic-three-r160.js`に用意する（`verify-pony.cjs`は`THREE_LOCAL`でも指定可能）。`node tools/verify-pony.cjs`、`node tools/verify-pony-export.cjs`、`node tools/analyze-pony-video.cjs`、`node tools/verify-pony-impact.cjs`を順に実行する。改修前は`PONY_VARIANT=before node tools/verify-pony.cjs`。ツールはローカルChromeとffmpeg/ffprobeのパスを指定しており、別環境では変更が必要。

再レビュー用の証跡は各コマンドに`PONY_OUT=docs/pony-validation/review`を付けて生成する。初回の履歴へ上書きせずに保存できる。
