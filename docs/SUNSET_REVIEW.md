# なぎさ夕景：劣化原因の分析と切戻し

**最新状態：picnicも同様の劣化を確認し、画面効果を切戻し済み。** [picnicの詳細設計・検証](LIGHTING_DESIGN.md#picnic夕景の確認切戻し2026-10-24)。以下はなぎさを先行調査した記録。

2026-10-24。対象：[光表現の改修方針](LIGHTING_PLAN.md)・[詳細設計](LIGHTING_DESIGN.md)。

## 結論と現在の実装

ユーザーが指摘したとおり、改修前にあった夕日の柔らかな広がりが試作で失われていた。主因は光芒の複数箇所での抑制。明部圧縮との組合せも、眩しさと黄白色の中心を弱めた。

なぎさは `createPixelRenderer` と `createLook` の新プロファイル有効化を撤回し、ブルーム・光芒・空中光・出力を旧方式へ戻した。`createLeafKit({ softDapple: true })` による木漏れ日の改善は保持。時刻だけで切り替える方式は日没前後の見た目の変動を増やすため採用せず、なぎさ全体の画面効果を元へ戻した。picnic・他ページの今回の設定は変更していない。

## 原因・劣化した要素

1. **夕日が低いほど光を消す設定になっていた。** `realsite/look.js` の `smooth(0,0.12,sunDir.y)` は、太陽が約0〜6.9度の範囲で効果を減衰させる。比較画像の太陽高度は1.391度。夕景を豊かにする目的と逆に、まさに日没直前の光を強く抑えていた。
2. **設定値の低下と描画側の倍率が重なった。** 従来の `warm*0.85` を `warm*0.5*daylight` に変更し、さらに描画側で0.35倍した。この画像のuniform値は0.835179→0.051285、描画側を含めると0.017950相当、**元の約2.15%（約97.85%減）**。太陽の周り、枝葉の縁、地平線を明るく包む成分が失われた。
3. **明部圧縮が光芒の復元後にも眩しさを抑えた。** 最大RGB成分が0.8を超えるとRGB比率を保って圧縮するため、旧方式のチャンネルごとのクリップで生じていた黄白色の芯が橙寄りに見える。色比率の保持は数値上成功していたが、今回の夕景の美しさを保つ条件では不十分だった。
4. **空中光も同時に抑制した。** 設定値0.741282→0.066671、距離60→28m、距離減衰・散乱方向・影範囲外判定も変更。単独比較では、この構図の広い光の消失への寄与は光芒より小さかった。
5. **ブルームの変更は、この広域の劣化の主因ではなかった。** 旧ブルームを単独で戻しても、下記環帯の値と広がりはほぼ戻らなかった。ただしブルームは1〜4ドットの近傍処理であり、この結果から太陽の芯や他場面で無影響とは判断しない。

画像上の劣化は、太陽周辺の光の裾の縮小、樹木と空の間を包む暖かな逆光の低下、地平線の明るさの低下、眩しい黄白色の中心が弱い橙色に変わったこと。形の識別性の向上だけを重視して、雰囲気を損ねていた。

## 切り分け方法と結果

[比較画像一覧](lighting-validation/sunset-review/index.html)。[機械可読の実験結果](lighting-validation/sunset-review/analysis.json)。再現スクリプト：`tools/review-sunset.cjs`。

夏、同一カメラ `[-68,11.7800003,46]`、同一時刻18.654957856、1280×720表示・320×180描画。時間とアニメーションを止め、24フレームの初回描画後に測定。HUDは全ケースで同じように非表示とした。改修前はコミット0394ced9のHTML・描画・look・樹木を読み、試作は変更したソースをブラウザのリクエスト応答で差し替えた。実アプリのソースを実験ごとに書き換えてはいない。

太陽中心から12〜48描画ドットの環帯6778画素で、表示RGBに重み0.2126/0.7152/0.0722を掛けた平均値と、0.7を超える画素の割合を比較。sRGB符号化後の画像指標であり、物理的な輝度・光エネルギー・美しさの点数ではない。画像の目視と併用した。

| 比較条件 | 環帯の平均値 | 明るい画素の割合 |
|---|---:|---:|
| 改修前（元ソース） | 0.531411 | 40.25% |
| 劣化した試作 | 0.408285 | 29.89% |
| 光芒だけ戻す | 0.495937 | 40.12% |
| 明部圧縮だけ戻す | 0.411642 | 29.89% |
| ブルームだけ戻す | 0.408275 | 29.89% |

光芒単独の復元で広がりの多くが戻り、光芒＋明部圧縮の復元で元に非常に近づいた。切戻し後の平均値は元の約99.94%、明るい画素の割合は一致。木漏れ日の模様を残しているため、画面全体が全画素一致したとは扱わない。

## 検証と判断の見直し

- 全8比較でJS・シェーダー・GLエラー0。
- 切戻し後のなぎさは新プロファイル0、光芒uniform0.835179を確認。画像指標の復元を回帰検査に追加。
- 低高度の夕景で旧lookの光芒が0.8以上を保つNodeテストを追加。全41テストは[実行結果](lighting-validation/sunset-review/tests.txt)を参照。
- 切戻し後の昼・見上げ・夕景・夜を撮り直し、[現在の描画時間](lighting-validation/after.json)も測定。GPU中央値はなぎさ2.398〜2.657ms。実行時の揺れを含むため、以前の値との差を確定的な速度改善とは呼ばない。
- [なぎさのブラウザ再検証](lighting-validation/regressions-nagisa.json)：0/6秒画像一致、PNG1280×720、6秒H.264動画の保存、保存後のidle・解像度復元、縦画面と移動を確認。

前回の「夕景の白っぽさを減らした」という評価は、今回の表現目標に対して不適切だった。機能・色比率・保存のテスト成功は、夕景の雰囲気の改善を保証しなかった。今後は元画像の逆光の裾・芯・明暗のつながりを維持することを受入条件にし、光芒・ブルーム・明部圧縮を分けて比較する。一括で強度を下げない。

旧方式へ戻したなぎさでは、HDR入力が強い場合のチャンネルごとのクリップと、影範囲外を明るいと扱う近似も従来どおり。新方式の「HDR色比率保持」「影範囲外の寄与ゼロ」のテスト条件はpicnicに限定し、なぎさの改善として引き続き主張しない。画面外の遮蔽を扱えない制約、実機・全季節の未検証も残る。

picnicにも同種の抑制設定は残っており、今後の見直し候補。この分析はなぎさの当該夕景で因果を検証したもので、他場面の美観まで一括で改善/劣化と判定していない。コミット・プッシュ・公開は実施していない。
